# 射频大模型的范式之争：基于 VLM 的内化感知 vs 基于智能体的工具协同

> 文献综述与对比分析报告

---

## 一、引言

### 1.1 背景：大模型浪潮与射频智能的交叉
- LLM / VLM 在文本、视觉、音频领域的成功
- 无线通信/射频领域对大模型能力的迫切需求
- 两种截然不同的技术路线同时兴起

### 1.2 核心问题
> 大模型应该"学会"理解射频信号，还是"调用"工具来分析射频信号？

## 二、路线A：基于 VLM 的内化感知

### 2.1 核心思想
- 将 RF 信号转为频谱图（图像形式）
- 利用 VLM 的视觉编码能力"看懂"频谱
- 通过微调将 RF 知识内化到模型参数中

### 2.2 代表工作详解

#### RF-GPT（Khalifa University, 2026）
- **架构**：IQ → STFT 频谱图 → ViT 编码器 → 线性投影 → Qwen2.5-VL LLM
- **数据**：MATLAB 合成，6 种无线技术，12K 场景，625K 指令对
- **成果**：WBMC 82.4%、WTR 99.64%、WBOD 91.5%
- **局限**：全合成数据、仅与基模对比、无真实信号验证

#### Seeing Radio（同团队, 2026）
- RF-GPT 的前序工作
- 三种可视化方式：时域轨迹/幅度谱图/联合表示
- 轻量微调：~10% → ~90%（57类调制）
- 证明了 VLM 从零学会 RF 感知的可能性

### 2.3 路线A的优势与劣势
**优势**：端到端简洁、单一模型统一多任务、演示效果好

**劣势**：
- 合成→真实的泛化鸿沟
- 需要大量高质量标注数据
- 黑箱推理，难以审计
- 仅限"识别"，无法控制硬件

## 三、路线B：基于智能体的工具协同

### 3.1 核心思想
- LLM 不做 RF 理解，而是做推理编排
- 通过工具调用（API/函数/数据库）获取专业分析结果
- 发挥 LLM 的长板（推理、规划、对话），回避短板（信号处理）

### 3.2 代表工作详解

#### AICEBERG（2026.04）
- **架构**：LLM → MCP（Model Context Protocol）→ SCPI → 频谱分析仪
- **亮点**：双服务器设计（执行 + 安全校验），自然语言→硬件指令
- **场景**：频谱监测、合规检查、干扰排查
- **意义**：第一次把 LLM+硬件控制 完整打通

#### WirelessAgent（2025.05）
- **架构**：LangGraph + 感知/记忆/规划/行动 四模块
- **成果**：网络切片带宽利用率 +44.4%，仅低于最优解 4.3%
- **代码**：GitHub 开源

#### WirelessAgent R1（2026.04）
- 在 CSI 缺失条件下做资源分配
- Agent + CSI 预测模型 + Coze 平台
- RMSE 降低 67%

#### Multi-LLM Agent DRL（KTH, 2025-2026）
- **混合架构**：每个基站/UE 一个 LLM Agent
- LLM 做高层协商，DRL 做低层控制（功率分配/波束赋形）
- 面向 6G 的 scalable 方案

#### raNora（Aircom 商用, 2026.03）
- **首个商用**电信 Agent AI 平台
- 多 Agent 系统：数据库 Agent + 覆盖 Agent 等
- 已用于真实网络规划和合规审计

### 3.3 路线B的优势与劣势
**优势**：
- 可调用已有成熟工具（传统信号处理、小模型、数据库）
- 推理过程可审计、可溯源
- 灵活扩展（加新任务 = 加新工具）
- 可控制硬件设备
- 已有商用落地

**劣势**：
- 系统架构复杂（多组件编排）
- 延迟较高（多次工具调用）
- LLM 推理可能有幻觉，需要校验机制

## 四、多维度对比分析

| 维度 | 路线A: VLM内化感知 | 路线B: 智能体协同 |
|------|------------------|-----------------|
| **核心假设** | 让LLM学会看频谱 | 让LLM调用工具分析频谱 |
| **数据需求** | 高（大量标注或合成数据） | 低（工具已有现成能力） |
| **真实信号泛化** | 差（合成→真实 gap） | 好（工具处理真实信号） |
| **硬件控制** | 不支持 | 支持（SCPI/API） |
| **可解释性** | 黑箱 | 可审计的推理链 |
| **扩展新任务** | 需重新微调 | 加工具即可 |
| **安全可控** | 模型可能幻觉 | 工具调用可校验 |
| **系统复杂度** | 低（单一模型） | 中高（多组件） |
| **学术发表** | 容易（新微调方法） | 较难（偏工程） |
| **产业落地** | 无 | 已有商用产品 |

## 五、案例研究：同一任务的两条路径

### 任务："分析当前频谱环境中是否存在非法干扰"

**路线A 的做法**：
1. SDR 采集 IQ → 频谱图
2. VLM 直接回答："检测到 2.4GHz 频段有非 WiFi 信号……"
3. 风险：误判无法追溯，没有法规数据库对照

**路线B 的做法**：
1. Agent 解析意图 → 调用频谱分析工具（传统算法 + 小模型）
2. 工具返回各信道的功率/占用/信号类型
3. Agent 调用 FCC 数据库查询本地频率分配
4. 综合判断："信道 6 存在未授权信号，功率 -30dBm，建议上报"
5. 每步可审计，可人工干预

---

## 六、总结与展望

### 6.1 两条路线的关系
- **不是互斥，而是互补**
- 理想架构可能是：**Agent 为主，VLM 为辅**
  - Agent 做编排、推理、决策
  - VLM 作为 Agent 的一个"工具"（处理频谱图）
  - 传统信号处理模型作为其他工具

### 6.2 未来方向
- 混合架构（Agent + VLM + 传统模型）
- Agent 安全性与可靠性增强
- 真实环境的大规模验证
- 标准化（MCP for RF/MCP for SCPI）

### 6.3 结论
> 对于"大模型 + 无线通信"这个方向，**智能体协同路线在工程落地和真实场景泛化上明显领先，VLM 内化感知路线在学术简洁性上有优势但距离实用尚远**。未来属于两者融合。
