## 第二部分：背景与意义（P3-P4）

### P3：项目背景

**现状痛点：**
- 传统肉类新鲜度判断依赖人工视觉，受经验、疲劳、主观因素影响大
- 市场上广泛存在的"生鲜灯"（暖色光源）严重干扰肉色判断，误导消费者
- 专业检测设备（pH计、TVBN检测仪）成本高、操作复杂、无法普及
- 现有AI方案多为纯云端部署，存在网络依赖、延迟高、隐私风险

**项目目标：**
构建一套**高可靠、低成本、易部署**的肉类品质智能检测系统：
- 用户通过手机拍照上传
- 云端 AI 算法自动判断新鲜度等级
- 可视化界面展示结果与置信度
- 支持历史记录查询

**技术路线：**
手机采集 → 云端AI推理 → 结果反馈（≤200ms）

**建议配图**：实际场景照片 —— `素材/测试素材/旋转小火锅-学校/`（旋转小火锅真实场景）和 `素材/测试素材/自助餐-某花/`（自助餐场景），用于展示真实复杂的餐饮环境

## 第三部分：系统架构（P5-P6）

### P5：技术栈

**整体架构：客户端-服务器（Client-Server）**

```
┌─────────────┐     拍照/上传      ┌──────────────┐
│  移动端APP   │ ────────────────── │   云服务器     │
│  (Android/iOS)│     结果返回      │  ONNX Runtime  │
└─────────────┘                    └──────────────┘
```

**关键技术选型：**

| 层级 | 技术 | 选型理由 |
|------|------|---------|
| 目标检测 | **YOLOv8** | 实时性好，精度高，小目标检测能力强 |
| 分类网络 | **MTxNet（轻量化）** | 仅0.29M参数，CPU推理4.62ms/张 |
| 模型部署 | **ONNX Runtime** | 跨平台，轻量，移动端支持好 |
| 数据增强 | **生鲜灯仿真** | 针对性解决生鲜灯干扰问题 |
| 后端推理 | **云端CPU服务器** | 成本低，可弹性扩展 |

### P6：处理流程

**完整处理链路：**

```
用户拍照 → YOLO检测肉类区域 → 区域裁剪(128×128) 
→ MTxNet分类推理 → 输出新鲜度等级(新鲜/半鲜/腐败) + 置信度
→ 结果展示 + 存储历史记录
```

**关键技术难点：**
- **YOLO层**：从复杂背景中精准分割肉类区域，排除餐盘、包装、标签等干扰
- **分类层**：在极轻量模型（<2MB）上保持高准确率（>90%）
- **鲁棒性层**：应对生鲜灯、不同光线、拍摄角度等真实场景变化

## 第四部分：核心技术（P7-P10）

### P7：YOLO目标检测 + 分类头

**问题背景：**
- 真实场景中肉类照片背景复杂（餐盘、案板、包装、标签等）
- 分类模型直接在全图上推理，背景干扰导致准确率大幅下降

**解决思路：** YOLO先定位肉类区域 → 裁剪后送入分类网络

**YOLO改进策略：**
- 使用 **YOLOv8n**（轻量版本）作为检测器
- 检测到肉类区域后，进行**区域裁剪 + 缩放**（统一为128×128）
- 再送入 MTxNet 分类网络进行新鲜度判别

**困境分析 —— 为什么必须用YOLO？**

当不使用YOLO检测，直接将全图送入分类网络时，注意力会偏移到背景区域而非肉类本身：

| 场景 | 问题 |
|------|------|
| 新鲜牛肉 | 注意力偏移至白色背景，模型判定依据错误 |
| 腐败猪肉 | 注意力分散到标签、包装膜等非目标区域 |
| 复杂场景 | 案板纹理、餐盘边缘等干扰严重 |

> **直观理解**：模型学会了"看盘子颜色判断肉新不新鲜"，而不是真正在学习肉的特征。

**YOLO加入后的改善效果：**

| 方案 | 准确率 | 说明 |
|------|:-----:|------|
| 无YOLO（全图直接分类） | ~75% | 注意力偏移，背景干扰严重 |
| **有YOLO（检测+裁剪+分类）** | **~88%**（**提升13%**） | 有效排除背景干扰 |

### P8：生鲜灯仿真数据增强

**问题起源：**
- 市场广泛使用"生鲜灯"（白光LED + 红光LED混光）
- 红色光谱增强使肉色更鲜红，掩盖腐败迹象
- 训练数据在标准光下采集，模型对红光偏移无免疫力

**生鲜灯效果展示（同一块腐败猪肉在不同功率下）：**

```
0%功率（白光） → 10% → 20% → 50% → 60% → 80% → 90% → 100%功率（满红光）
  （真实颜色）                                   （鲜红误导色）
```

可以看到：随着红光LED功率增大，肉色从暗灰逐渐变为鲜红，**腐败肉在100%功率下看起来与鲜肉无异**。

**仿真模型原理：**

基于物理光谱特性，采用**全参数联动线性插值**：

```
R' = min(255, R × red_strength)      # 红色通道增强
G' = max(0, G × (1 - green_decay))   # 绿色通道衰减
B' = max(0, B × (1 - blue_decay))    # 蓝色通道衰减
```

| 参数 | 0% 功率 | 100% 功率 | 物理含义 |
|------|:-------:|:---------:|---------|
| red_strength | 1.0 | 1.4 | 红色通道增益 |
| alpha | 1.0 | 1.2 | 对比度系数 |
| beta | 0 | 25 | 亮度增量 |
| gamma | 1.0 | 0.9 | Gamma校正 |

**增强策略：**
- 每张原图随机生成 20%-80% 功率的生鲜灯版本
- 训练集中生鲜灯增强图与原图合并（3630张）
- 同时引入 4×4 分块空间扰动 + 高斯噪声

**核心优势：**
> 无需实际采集生鲜灯场景数据，仅通过仿真增强即可使模型适应真实生鲜灯环境

**建议配图**：`素材/实验数据与实验图表/生鲜灯仿真0-100%-共8张选择即可/` 下的全部8张图

> **PPT排版建议**：选择其中3-4张典型功率（0%、20%、50%、100%）横向排列，形成"功率递增→肉色渐红"的视觉序列，让观众直观感受生鲜灯的欺骗性。这是整个PPT中最有视觉冲击力的一组图。

### P9：数据预处理策略

**消融实验设计（控制变量）：**
> 固定 MobileNetV2 架构，不引入预训练和知识蒸馏，隔离数据增强的纯粹影响

| 组别 | 增强策略 | 训练集大小 |
|------|---------|-----------|
| **A（基线）** | 仅 Resize + Normalize | 1815张 |
| **B** | ColorJitter（颜色抖动） | 1815张 |
| **C** | 生鲜灯仿真增强 | 3630张（原图 + 生鲜灯版） |
| **D** | ColorJitter + 生鲜灯 | 3630张 |

**核心发现（5个测试场景的平均表现）：**

| 模型 | 正常 | lamp 0% | lamp 20% | lamp 50% | lamp 80% |
|------|:---:|:-------:|:--------:|:--------:|:--------:|
| **A（基线）** | 86.47% | 86.03% | 85.59% | 85.37% | 82.93% |
| **B（ColorJitter）** | 85.59% | 85.59% | 82.71% | 78.94% | 74.50% |
| **C（生鲜灯增强）** | **89.14%** | **89.14%** | **90.91%** | **88.47%** | **89.58%** |
| **D（两者叠加）** | 88.25% | 88.03% | 88.69% | 87.80% | 85.37% |

**结论：**
1. **C组（仅生鲜灯增强）全面最优** —— 在所有测试条件下准确率最高，且波动最小
2. **B组（ColorJitter）表现最差** —— 80%功率下仅 74.50%，比基线还低8%
3. **ColorJitter在此任务中有害无益** —— 肉类颜色本就是判断新鲜度的关键特征，随机变色干扰了判断

### P10：MTxNet 轻量化网络设计

**设计约束：**
- 模型文件 < 2MB
- 单次推理时间 < 200ms（含网络传输）
- 准确率 > 90%

**MTxNet 架构亮点：**

参考 MobileNetV2 的倒残差（Inverted Residual）结构，针对移动端部署极致压缩：

| 指标 | MTxNet | MobileNetV2 | ResNet-18+ECA |
|------|:-----:|:-----------:|:-------------:|
| 参数量 | **0.29M** | 3.50M | 11.20M |
| 模型大小 | **~1.2MB** | ~14MB | ~45MB |
| CPU推理 | **4.62ms** | 14.08ms | 17.28ms |
| GPU推理 | 9.21ms | **3.79ms** | 11.33ms |

**关键优化点：**
- 倒残差瓶颈结构（Depthwise Separable Convolution）
- 通道数精细裁剪（从 MobileNetV2 的 3.5M 降至 0.29M，压缩 **12倍**）
- 移除全连接层，使用全局平均池化 + 分类头
- 导出 ONNX 格式，使用 ONNX Runtime 推理

**核心优势：** 在云端 CPU 上 4.62ms/张，单核即可支撑约 **216 QPS** 的并发处理能力。

**建议配图**：`素材/实验数据与实验图表/消融实验2-不同cnn网络结构的准确度，混淆矩阵，推理时间11对比/模型对比.png`

> 这张图从参数量、准确率、GPU推理时间、CPU推理时间等多个维度横向对比三种模型，适合放在P10或P11作为主图。建议在PPT中放大突出CPU推理时间那组柱状条——MTxNet的4.62ms显著短于其他两者。

## 第五部分：实验结果（P11-P14）

### P11：模型大小 + 推理速度对比

**模型尺寸对比：**

| 模型 | 参数量 | 文件大小 | GPU推理 | CPU推理 |
|------|:-----:|:-------:|:-------:|:-------:|
| ResNet-18+ECA | 11.20M | ~45MB | 11.33ms | 17.28ms |
| MobileNetV2 | 3.50M | ~14MB | **3.79ms** | 14.08ms |
| **MTxNet** | **0.29M** | **~1.2MB** | 9.21ms | **4.62ms** |

**云端部署场景分析（为什么选MTxNet）：**

| 因素 | 云端特点 | MTxNet适配情况 |
|------|---------|---------------|
| CPU为主 | GPU实例价格是CPU的5-10倍，多数推理节点为纯CPU | ✅ CPU推理4.62ms，三者最快 |
| 并发需求 | 单节点多路请求，低延迟是关键 | ✅ 4.62ms/张 ≈ 216 QPS |
| 成本敏感 | 按资源付费，参数量越少成本越低 | ✅ 仅0.29M参数 |
| 冷启动 | 模型加载速度影响弹性伸缩 | ✅ 1.2MB秒级加载 |

### P12：准确率数据 + 混淆矩阵

**各模型分类准确率（验证集451张，三分类：新鲜/半鲜/腐败）：**

| 模型 | 准确率 | 参数量 | 综合评价 |
|------|:-----:|:------:|---------|
| **ResNet-18+ECA** | **99.78%** | 11.20M | 精度最高，但模型过大不适合轻量化部署 |
| **MobileNetV2** | **98.89%** | 3.50M | 良好的精度-大小平衡 |
| **MTxNet** | **95.34%** | **0.29M** | 🏆 **精度-尺寸-速度最佳平衡点** |

**MTxNet 混淆矩阵：**

| 真实\预测 | 新鲜 | 半鲜 | 腐败 | 合计 |
|---------|:---:|:----:|:----:|:----:|
| **新鲜（Fresh）** | 169 | 9 | 0 | 178 |
| **半鲜（Half-fresh）** | 7 | 147 | 5 | 159 |
| **腐败（Rotten）** | 0 | 0 | **114** | 114 |

**关键发现：**
- **腐败（Rotten）检测全部正确**（114/114）—— 最关键的食品安全指标零漏检 ✅
- 新鲜/半鲜之间少量混淆（共21张），属边界样本的正常难度
- 即使经过 **12倍参数压缩**，MTxNet 仍保持 **95%+** 准确率

**关于预训练+知识蒸馏的补充：**
- 引入 ImageNet 预训练 + 知识蒸馏后，所有模型准确率提升至 **98%以上**
- 各组间差异压缩至 < 1.5%
- **结论**：数据增强在无预训练时至关重要；有预训练时边际收益被稀释

**建议配图**：可在PPT中将混淆矩阵可视化为热力图风格（绿色正确/红色错误），增强视觉冲击力。原数据来自 `素材/实验数据与实验图表/消融实验2-不同cnn网络结构的准确度，混淆矩阵，推理时间11对比/实验所有数据与混淆矩阵等.md`，可据此在PPT中绘制彩色混淆矩阵图。

### P13：生鲜灯鲁棒性实验

**实验设计：** 对验证集施加不同功率生鲜灯效果（0%/20%/50%/80%），测试各模型表现

**核心数据：**

| 模型 | 正常 | 0%功率 | 20%功率 | 50%功率 | 80%功率 |
|------|:---:|:------:|:-------:|:-------:|:-------:|
| A（基线，无增强） | 86.47% | 86.03% | 85.59% | 85.37% | 82.93% |
| **C（生鲜灯增强）** | **89.14%** | **89.14%** | **90.91%** | **88.47%** | **89.58%** |
| D（叠加ColorJitter） | 88.25% | 88.03% | 88.69% | 87.80% | 85.37% |

**分析结论：**
1. **C组全面最优**：所有测试条件下准确率最高，波动极小（88.47% ~ 90.91%，**振幅仅 ±1.2%**）
2. **A组基线下降明显**：80%功率下 82.93%（降幅3.5%），基础模型对生鲜灯容忍度有限
3. **C组比A组最高提升 6.65%**（80%功率下：89.58% vs 82.93%）
4. **B组验证了策略方向**：针对性增强（生鲜灯）远优于通用增强（ColorJitter）
